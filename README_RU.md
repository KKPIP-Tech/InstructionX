## Введение

InstructionX — это **плагинно-ориентированный фреймворк настольных приложений** на базе PySide6. Он объединяет в единой инфраструктуре горячую замену плагинов, интеграцию больших языковых моделей (LLM) от нескольких поставщиков, двустороннюю поддержку протокола MCP, персистентность данных и управление фоновыми задачами, позволяя пользователям свободно комбинировать инструментальные плагины под свои рабочие процессы и создавать персональный универсальный набор инструментов (Tools Cluster).

Сам фреймворк не содержит бизнес-функциональности: все возможности подключаются в виде плагинов и распространяются через экосистему GitHub-репозиториев плагинов. Разработчики могут быстро создавать и публиковать собственные плагины на основе стандартизированных интерфейсов плагинов, контейнера служб с внедрением зависимостей и библиотеки компонентов UIKit.

> Это прикладной проект: он запускается непосредственно из исходного кода и не распространяется в виде библиотеки.

## Основные возможности

### Система плагинов

- **Управление жизненным циклом**: горячая загрузка / выгрузка / перезагрузка плагинов без перезапуска приложения; при удалении автоматически очищаются связанные данные, такие как идентификатор плагина и языковые переопределения
- **Установка и обновления**: встроенный установщик GitHub поддерживает репозитории с одним плагином (IXPlugin.json) и с несколькими плагинами (IXRepo.json), установку в фоновом режиме с отображением прогресса; локальная установка из zip (автоматическое распознавание пакетов с одним или несколькими плагинами и многоуровневой вложенности внутри архива, перед установкой показывается предварительный просмотр типа операции (обновление / переустановка / понижение версии), понижение версии требует повторного подтверждения), обновление / понижение версии через GitHub Release с определением отношений версий; репозитории организации KKPIP-Tech автоматически классифицируются как официальные плагины
- **Управление версиями и идентичностью**: семантические версии плагинов (alpha / beta / pre-release / release) и UUID-идентификатор каждого плагина; реестр установленных плагинов хранит версию / источник / время установки и служит основой для обновлений и проверки обновлений; Python-зависимости, объявленные плагинами, устанавливаются фреймворком автоматически (в первую очередь uv, при его недоступности — pip)
- **Взаимодействие между плагинами**: объявление `service_api` автоматически регистрирует межплагинные API и предоставляет их как инструменты MCP; плагины также могут напрямую регистрировать инструменты для LLM через `llm_tools`
- **Организация панели**: панель навыков поддерживает пользовательские группы, сворачивание и смешанный порядок; при переключении плагинов состояние интерфейса кэшируется и полностью восстанавливается при возврате

### Интеграция LLM

- **Поддержка нескольких поставщиков**: пять встроенных предустановок — MiniMax, SiliconFlow, Zhipu GLM, Ollama и OpenAI — плюс резервный адаптер `openai-compatible`, позволяющий без единой строчки кода подключить любую OpenAI-совместимую конечную точку
- **Управление несколькими диалогами**: создание / переключение / сохранение диалогов, автоматическое усечение контекста на основе оценки токенов при превышении окна (системный промпт и последние сообщения сохраняются)
- **Автоматизация вызовов инструментов**: ToolCallExecutor автоматически обрабатывает многошаговый цикл вызовов инструментов (по умолчанию `max_turns=5`); плагину достаточно зарегистрировать свои инструменты
- **Мультимодальность**: понимание изображений (Vision), генерация изображений, синтез речи TTS и векторные представления (Embedding)
- **Статистика использования**: учёт расхода токенов и оценка стоимости по диалогам и в целом, со встроенной панелью визуализации (AI → Использование)

### Двусторонняя поддержка протокола MCP

- **MCP-сервер**: автоматически предоставляет все API плагинов как инструменты MCP по транспортам stdio и HTTP, с опциональной Bearer-аутентификацией; MCP-клиенты, такие как Claude Code, могут напрямую вызывать возможности плагинов
- **MCP-клиент**: подключается к внешним MCP-серверам и регистрирует их инструменты в локальном ToolRegistry для вызова LLM
- **Двусторонний мост**: MCPBridge автоматически синхронизирует реестр API плагинов с MCP-сервером

### Персистентность данных

- **SQLite WAL + явные транзакции**: бэкенд по умолчанию, устойчивый к внезапным сбоям; через переменную окружения доступен JSON-бэкенд
- **Два пространства имён**: пространство PRIVATE видно только внутри плагина; пространство PUBLIC обеспечивает обмен данными между плагинами
- **Публикация / подписка**: плагины могут подписываться на изменения данных для реактивного взаимодействия; кэш в памяти сокращает дисковый ввод-вывод

### Система фоновых задач

- **Асинхронные задачи в пуле потоков**: четыре рабочих потока не блокируют интерфейс
- **Плановые и длительные задачи**: повторяющееся выполнение с фиксированным интервалом; длительные задачи поддерживают корректную остановку и автоматический перезапуск
- **Персистентность задач**: состояния задач сохраняются между перезапусками и автоматически восстанавливаются через механизм фабрики задач

### Интернационализация (i18n)

- **XML-файлы локализации**: фреймворк и плагины следуют соглашению «один XML-файл на язык»; встроены китайский (по умолчанию), английский, русский и французский языки
- **Мгновенное переключение**: мгновенная смена языка интерфейса через меню Правка → Язык без перезапуска
- **Цепочка резервных вариантов (fallback)**: строки, отсутствующие в текущем языке, автоматически подставляются из языка по умолчанию
- **Языковое переопределение для каждого плагина**: отдельный плагин может использовать язык интерфейса, отличный от языка фреймворка

### Пользовательский интерфейс

- **Библиотека компонентов InstructionX_UIKit**: 58 компонентов + 13 макетов + 52 анимации, включая собственный движок диаграмм (двойной вьюпорт GL / программный), граф узлов blueprint, редактор кода в стиле VS Code и рендеринг Mermaid; три глобальных режима темы (светлая / тёмная / авто) с дизайн-токенами, мгновенно применяющими оформление
- **Менеджер шрифтов**: установка / удаление / предпросмотр шрифтов на уровне приложения (действует в рамках процесса, без записи в системный каталог шрифтов), с автоматическим переходом на системные шрифты при их отсутствии
- **Системный трей**: меню трея в реальном времени показывает запущенные плагины и фоновые задачи; при закрытии главного окна отображается диалог подтверждения с выбором — выйти из программы или свернуть в трей

## Быстрый старт

### Вариант A: мастер TUI (рекомендуется для пользователей без опыта разработки)

**Дважды щёлкните** `setup.bat` (Windows) или `setup.command` (macOS).

Мастер — это **нативный скрипт** (Windows: PowerShell 5.1; macOS: встроенный bash), которому
**не нужны ни Python, ни какие-либо сторонние пакеты** — он работает даже на машине, где Python отсутствует вовсе:

```powershell
# Windows (командная строка, необязательные параметры)
powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1            # открыть мастер на китайском/английском
powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1 -Check     # только проверка состояния среды с отчётом
```

```bash
# macOS (командная строка, необязательные параметры)
./setup.sh            # открыть мастер на китайском/английском
./setup.sh --check    # только проверка состояния среды с отчётом
```

Мастер охватывает **установку / восстановление среды, обновление фреймворка, управление средой, проверку состояния в один клик, очистку и удаление, а также запуск приложения**, с подсказками на понятном языке, автоматической подготовкой uv и Python 3.14, конкретными рекомендациями при сбоях и полным журналом в `logs/tui_setup.log`. Интерфейс на обеих платформах идентичен вплоть до символа. См. [Мастер установки](docs/tui-setup.md) (на китайском, с резюме на английском).

### Вариант B: ручная установка (для разработчиков)

#### Требования

- Windows 10 / 11 (основная целевая платформа; macOS также поддерживается, но часть системных интеграций ограничена)
- Python 3.14 или новее
- [uv](https://docs.astral.sh/uv/) (менеджер виртуальных окружений и зависимостей Python)

#### Установка uv

```bash
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

#### Установка зависимостей

Первый запуск `uv run main.py` автоматически создаёт виртуальное окружение и синхронизирует зависимости по `uv.lock`; их также можно установить явно заранее:

```bash
uv venv
uv pip install -r requirements.txt
```

> Примечание: **не** используйте `uv sync` для восстановления существующего окружения — команда строго приводит окружение к `uv.lock` и **удаляет** дополнительно установленные в нём пакеты (например, зависимости плагинов, установленные через DependencyManager фреймворка, или тестовые зависимости). При **чистой** установке (каталог `.venv` ещё отсутствует) допустимо `uv sync --no-dev --no-install-project` (именно так поступает мастер TUI).

#### Запуск

```bash
uv run main.py
```

Каталоги `data/` и `config/` создаются автоматически при первом запуске.

## Экосистема плагинов

InstructionX — это фреймворк с плагинной архитектурой, встроенных бизнес-плагинов в нём нет. Способы получения плагинов:

- **Установка из GitHub**: меню «Правка → Установить плагин из GitHub...» — введите URL репозитория плагина для установки в один клик
- **Ручная установка**: скопируйте плагины, полученные от сторонних разработчиков, в каталог `custom_plugin/`

### Структура плагина

Каждый плагин — это подкаталог первого уровня в `plugin/` (официальные) или `custom_plugin/` (сторонние):

```
my_plugin/
├── entrance.py      # Обязателен: точка входа плагина, определяет подкласс IPlugin
├── information.py   # Обязателен: метаданные плагина (подкласс IPluginInfo: версия, значок, service_api и т.д.)
├── service.py       # Обязателен: сервис плагина / слой публичного API
├── config/          # Обязателен: каталог конфигурации плагина
├── text/            # Обязателен: каталог языковых пакетов (<код-языка>.xml, один файл на язык)
└── assets/          # Опционально: каталог статических ресурсов
```

Если указан `service_api` и имя класса сервиса оканчивается на `Service`, фреймворк автоматически регистрирует межплагинный API и синхронизирует его как инструменты MCP.

### Метаданные плагина

Репозиторий плагина описывает каждый плагин через `IXPlugin.json`, где поля `name` и `description` поддерживают многоязычные значения:

```json
{
    "id": "my-plugin",
    "name": {"zh": "我的插件", "en": "My Plugin"},
    "version": "release.1.0.0",
    "main": "entrance.py",
    "description": {"zh": "插件简介", "en": "Short description."},
    "author": "Your Name",
    "keywords": ["instructionx", "plugin"]
}
```

Репозитории с несколькими плагинами дополнительно требуют индексный файл `IXRepo.json`.

### Службы фреймворка, доступные плагинам

При создании экземпляра плагина фреймворк автоматически внедряет контейнер `PluginServices`, предоставляя плагину прямой доступ ко всей инфраструктуре фреймворка:

| Служба | Описание |
|--------|----------|
| `services.llm_facade` | Фасад LLM-служб для плагинов: несколько диалогов, вызовы инструментов, мультимодальность, статистика использования |
| `services.data_provider` | Слой данных DataProvider: пространства имён PRIVATE / PUBLIC, публикация / подписка |
| `services.task_manager` | BackgroundTaskManager: асинхронные / плановые / длительные задачи |
| `services.logger` | Интерфейс журналирования (ILogger) |
| `services.mcp_manager` | Управление MCP-сервером: предоставление API плагинов как инструментов MCP |
| `services.mcp_client` | MCP-клиент: подключение к внешним MCP-серверам |
| `services.font_manager` | Менеджер шрифтов: разрешение шрифтов с цепочками резервных вариантов |
| `services.localization` | Фасад i18n (привязан к UUID плагина) |

### Минимальный пример плагина

```python
from core import IPlugin
from PySide6.QtWidgets import QWidget, QLabel, QVBoxLayout

class MyPlugin(IPlugin):
    @property
    def plugin_name(self) -> str:
        """Имя, отображаемое на панели навыков"""
        return "Мой\nплагин"

    @property
    def skill_description(self) -> str:
        return "Это пример плагина"

    def _create_widget(self, parent=None, data_provider=None):
        """Создаёт интерфейс плагина"""
        widget = QWidget(parent)
        layout = QVBoxLayout(widget)
        layout.addWidget(QLabel("Hello from MyPlugin!"))
        return widget
```

## Конфигурация и данные

Следующие файлы создаются при запуске; не изменяйте их структуру вручную:

| Файл | Назначение |
|------|------------|
| `config/llm_providers.json` | Конфигурация экземпляров LLM-поставщиков (API-ключи хранятся в обфусцированном виде) |
| `config/llm_models_cache.json` | Кэш списков моделей |
| `config/mcp_config.json` | Конфигурация MCP-сервера / клиента |
| `config/plugin_order.json` | Порядок отображения несгруппированных плагинов |
| `config/plugin_groups.json` | Пользовательские группы плагинов и порядок на панели |
| `config/plugin_registry.json` | Реестр установленных плагинов (основа для обновления / понижения версии) |
| `config/i18n.json` | Языковые настройки фреймворка |
| `config/plugin_languages.json` | Языковые переопределения для каждого плагина |
| `data/data.db` | Данные плагинов (SQLite + WAL) |
